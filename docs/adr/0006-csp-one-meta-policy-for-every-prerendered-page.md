# 0006. One meta CSP for every prerendered page

`<ClientRouter />` keeps one document and swaps pages into it, and a `<meta>` CSP binds the document it was parsed with. Astro writes a per-page meta policy hashing only that page's inline scripts, so after the first soft navigation the next page's islands would be blocked. This breaks only under soft navigation, never on a direct load, so nothing catches it by hand.

Every prerendered page carries the same meta CSP: the union of all of them. `shared/csp-union.ts` computes it as pure string work (`metaPolicies`, `unionPolicies`, `replaceMetaPolicy`) so it tests under `node --test`; `scripts/csp-union.ts` `unifyCsp` does the file IO, refuses a page with other than exactly one CSP meta tag, and rewrites every page's meta to the union. It runs as the `csp-union` integration on `astro:build:done` in `astro.config.ts` rather than as an npm script, so it runs whatever command starts the build, Workers Builds included. A test in `shared/security.test.ts` asserts that all prerendered routes get one identical CSP, because the middleware's `harden()` preserves a route-set CSP rather than overwriting it, which makes a route-varying policy easy to introduce.

`unionPolicies` merges directive by directive, keeping every source any policy names in first-seen order. Union is right for allow-lists of hashes and hosts. It would be wrong for directives whose sources narrow each other, but Astro's meta carries only `script-src`, `style-src` and their `-attr`/`-elem` forms. If Astro is ever passed other directives, this has to be revisited.
