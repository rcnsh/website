# 0079. Thumbs are backfilled by the owner and served to everyone

Drawing a waveform or a video strip in the browser downloads the whole file. The owner can instead run a backfill (`Backfill` in `src/components/react/MediaPreview.tsx`) that stores posters, strips and peaks once, and every visitor then reads them. `buildThumbs` (`src/lib/media-preview.ts`) has no file-size cap, so the owner's backfill is uncapped, while visitors get no in-browser waveform for audio over `VISITOR_WAVEFORM_MAX_BYTES` (64 MiB): the backfill runs once for the owner and its results are stored for every visitor.

Owner-only preview UI is hidden by default until the owner probe (`checkOwner`, a GET of `/api/files/thumbs`) confirms the owner, so visitors never see the controls even briefly. `GET /api/files/thumbs` answers `{ owner: false }` with a 200 to anyone but the owner, so the thumb presence of private files does not leak, and a non-2xx (throttled, down) is not an answer: the probe is cached for the visit only on success and retried later otherwise. A failed probe clears `ownerCheck` only if it is still the current probe, since a later visit may have started a new one that must not be dropped.

`folderThumbs` (`src/lib/media.ts`) does a live R2 listing of `.thumbs/<prefix>` and is owner-only: a live listing is accurate right after a backfill write but too costly to expose to visitors. Per-file thumbs presence is cached for one hour (`THUMBS_FRESH_SECONDS`), because thumbs appear only when the owner backfills and the upload route clears the entry then. Thumb objects use the `thumbObject` cache policy (`public, max-age=86400`, `src/lib/http.ts`), not an immutable one, because regenerating thumbs overwrites the same key.

Backfill uploads retry a 429 up to 4 times, waiting `Retry-After` seconds (default 30), because the thumbs route is rate-limited and a long backfill should back off rather than fail. Before starting, the backfill checks that `canvas.toDataURL('image/webp')` produces WebP and refuses to run if not: Safari hands back a PNG, and thumbs are stored as `.webp`, so every file would fail in turn. What the route accepts is in ADR-0078.
