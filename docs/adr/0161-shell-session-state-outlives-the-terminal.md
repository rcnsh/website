# 0161. Shell session state outlives the terminal it runs in

The palette mounts a new terminal on each page, since soft navigations replace the page's markup, but scripts run once per document. The shell's working directory and history therefore live in a `SessionState` object owned by the palette (`src/lib/shell-session.ts`), separate from any terminal. `src/components/CommandPalette.astro` holds it as a module-level promise, `shellLoad`, with a banner flag, so the working directory, history and downloaded filesystem carry across soft navigations. Storing the promise rather than its value lets pages that ask while the load is in flight share one fetch.

If loading `/shell-fs.json` fails, `shellLoad` is reset so the next `$` retries, and the palette shows an error line instead of a terminal; without that guard a prompt would appear over a shell whose filesystem never arrived and answer every command as if the site were empty. Once the filesystem has loaded the state is kept even if mounting fails, so a later failure does not throw away the visit's working directory and history.

The session drives the shell through an injected `SessionHost` (`write`, `cols`, `navigate`, `exit`) and imports nothing from wterm or the DOM, so its logic tests under node. After `exit`, `feed()` ignores the remaining keys of the same chunk until `start()` is called again, so a pasted `exit` followed by more commands does not keep running commands in a terminal that has handed back to search. The host's `navigate` waits 180 ms before calling `navigate()`, cancelled if the page leaves first, so the reader sees the `Opening …` line land before the page changes.
