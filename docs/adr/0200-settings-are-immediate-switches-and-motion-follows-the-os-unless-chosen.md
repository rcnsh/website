# 0200. Settings are immediate switches, and reduced motion follows the OS unless the reader chose

`src/components/SettingsMenu.astro` offers two settings, Live updates and Reduce motion. There is no form: a setting applies as soon as it is clicked, which is switch semantics, so each is a `<button role="switch" aria-checked>` rather than a checkbox. A setting's `key` (`live`, `motion`) is at once the `PrefKey` in `src/lib/prefs.ts`, stored as `rcn:<key>`, and the `data-settings-toggle` value the script looks the switch up by; renaming one without the other silently unbinds the switch from its stored preference.

Reduced motion follows `prefers-reduced-motion` (`REDUCED_MOTION_QUERY` in `src/lib/prefs.ts`) unless the reader has stored an explicit choice under `rcn:motion`, which wins in either direction (`motionReduced`). A stored null means never chosen, not off. This respects the OS setting by default while letting the site's switch override it both ways. Until the reader touches the switch it reports the OS setting, so the script listens for change events on `REDUCED_MOTION_QUERY` and re-applies motion and updates the switch as the OS setting changes.

The resolved value is published as `data-motion="reduce"` or `"full"` on `<html>` by the bootstrap script before first paint, wherever there is script. Reduced motion is applied through `:root[data-motion="reduce"]`, not `@media (prefers-reduced-motion)` alone, because the site's own switch must be able to override the OS setting and only the attribute reflects the reader's choice. `src/styles/global.css` honours that attribute and also the `prefers-reduced-motion` media query for documents without it, which covers the case where no script runs.

`[data-settings]` is `display: none` until the script sets `data-settings-ready`: before then the cog does nothing, so it is not shown. The cog renders at 14px (`h-3.5 w-3.5`) to align with the ⌘K label beside it, with `p-2.5` cancelled by `-m-2.5` so the hit target grows without moving the icon.
