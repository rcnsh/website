# 0028. The owner is a GitHub user id, checked by one guard

The owner is the session whose GitHub numeric user id equals `OWNER_GITHUB_ID` (`wrangler.jsonc`), not a login. Numeric ids are stable where usernames can be renamed and then reclaimed by someone else. The id gates every owner-only route, such as `/api/files/thumbs`. If the variable is unset, non-numeric, or not a positive safe integer, nobody is the owner, so a misconfiguration never grants owner access.

Every owner check goes through `requireOwner` or `identify` (`src/lib/owner.ts`, decisions in `src/lib/owner-guard.ts`). `ownerGuard` takes the session lookup as a parameter so its decisions test under node without the Worker runtime. A non-owner is refused in one of four styles: `forbidden` (403), `not-found` and `not-found-json` (404s matching the route's own), or `visitor` (`{ owner: false }`, `private, no-store`) for the GETs the browser uses to ask whether it is the owner. Where a 403 would confirm that the thing exists, such as a private file, the refusal must look like the route's own 404. `/blog/edit` follows the same rule: a signed-in non-owner gets a plain 404 (`refuse(Astro, "not-found")`), so someone else's session learns nothing about the editor existing, while a signed-out visitor gets the sign-in prompt.

With `sameOrigin: true`, `requireOwner` returns 403 for a cross-origin request before any session lookup, so a cross-origin write is refused without touching D1 and regardless of the cookie. The guard sets `locals.owner`, and the middleware stamps `private, no-store` on every response where it is set, whatever the route sets, because an owner response may contain private data and must never be cached for anyone else.
