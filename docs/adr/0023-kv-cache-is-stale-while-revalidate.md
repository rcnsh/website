# 0023. The KV cache is stale-while-revalidate

`cached(key, freshForSeconds, loader, { maxStaleSeconds })` in `src/lib/cache.ts` is stale-while-revalidate over the `CACHE` KV namespace: only a cold miss blocks, a stale hit is served while a refresh runs in the background, and every entry is written with `expirationTtl` of the fresh window plus `STALE_GRACE_SECONDS` (30 days). `maxStaleSeconds` (default `STALE_GRACE_SECONDS`) bounds how old a stale value may be served; it exists for date-anchored data that looks plainly wrong when weeks old. Past it, `cached()` waits for a fresh load, but returns the stale value if that load fails, since a stale value still beats an error.

The logic is `createCache` in `src/lib/swr.ts`, which takes the store, clock and `waitUntil` as dependencies; `src/lib/cache.ts` binds them to KV. `cache.ts` imports `cloudflare:workers`, which does not load under `node --test`. The store dependency is a function read on every call, because the `CACHE` binding can be absent (some local and prerender contexts); then `cached()` only coalesces the loader and caches nothing rather than failing. The background refresh calls `waitUntil` inside `try`/`catch`, because `waitUntil` throws outside a request context such as prerendering; the refresh may then not finish. `src/lib/swr.test.ts` simulates KV expiry by deleting the entry, since real KV evicts at `expirationTtl` and the fake does not.
