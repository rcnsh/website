# 0010. Non-script directives live only in the header policy

Astro's meta CSP carries only `script-src` and `style-src`. Every other directive (`connect-src`, `img-src`, `media-src`, `default-src` and the rest) therefore binds from the header alone, and `astro.config.ts` passes Astro no `directives`. The moment it does, the hosts in those directives must be in both policies. `worker-src` is the trap: it falls back to `script-src`, which the meta binds.

These directives are `baseDirectives()` in `shared/security.ts`. `BUCKET_ORIGIN` (`https://upload.rcn.sh`, the same origin as the `PUBLIC_BUCKET_URL` var in `wrangler.jsonc`) is named in `img-src`, `media-src` and `connect-src`, because /files previews read the bucket three ways: posters as images, playback as media, and Mediabunny's ranged reads as fetches. `shared/security.test.ts` asserts each one, since with one missing the other half of a preview still works and hides the breakage. The routes read the bucket's address from `PUBLIC_BUCKET_URL` instead, and the upload Worker is routed on its host in `workers/upload/wrangler.jsonc`; the same test file parses both configs and fails when either names a different origin, so moving the bucket means changing all three together. A test, not generation, because the constant is also bundled into the browser (`parseSavedPlayback` in `player.ts`) and `shared/` stays free of build-time inputs. `media-src` also includes `'self'`, because private files play through the same-origin `/api/files/download` route rather than the bucket origin. `img-src` allows `https://*.scdn.co` and `https://*.spotifycdn.com` by wildcard because Spotify serves album art from several subdomains.
